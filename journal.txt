CLASSIFICATION FIXES (scanUtils.ts):
- awaiting_reply now requires ALL THREE: owner sent ≥1 message, their last msg had
  unanswered question, other party hasn't responded
- Cold outreach: third party emailing owner with no reply = awaiting_action/new, NOT awaiting_reply
- Cold outreach follow-up chase ("just following up") explicitly blocked from awaiting_reply
- Self-consistency check: if NEXT STEP says owner needs to act → status must be awaiting_action
- ownerHasReplied computed from actual message headers in scan + background-scan + reanalyse routes
  Hard override in code: if ownerHasReplied=false and AI returns awaiting_reply → force awaiting_action
- Thread context backoff (buildThreadContext):
  Latest message: uncapped (*** LATEST MESSAGE *** label)
  Positions 2-3: 1200 chars
  Positions 4-6: 500 chars
  Positions 7-10: 250 chars
  Position 11+: 100 chars
- Recency weighting: LATEST MESSAGE labelled, strong next-turn ownership rules
- Document/statement availability: score 0.15-0.20, quietly_logged (bank statements, HMRC docs)
- SCORING BANDS (revised):
  0.95: overdue payment, legal/medical action required
  0.88-0.92: today/tomorrow event/deadline/commitment → Urgent
  0.82-0.87: payment due ≤7 days, RSVP imminent
  0.75-0.80: non-payment response deadline ≤7 days → High (not Urgent)
  0.70-0.75: action needed, not urgent
- Proximity override in code (classifyThread + reanalyse): any signal ≤2 days → score ≥0.88
- Date accuracy rule: read month from email context, not current month
  ("the 16th" in a June discussion = June 16th, not May 16th)
- Travel disruption alerts: quietly_logged (Trainline, National Rail, airlines)
- Security alerts: status=new, score 0.35-0.45 (not awaiting_action unless explicitly compromised)
- Promotional offers with prices: quietly_logged — price in offer ≠ payment signal
- Marketing/promotional emails: quietly_logged
- Calendar reminder skip improved (subject patterns + known senders)

POST-SCAN EXPIRY (/api/admin/expire-items — NEW):
- Runs per-user expiry + proximity rescore on demand
- Called fire-and-forget after every scan (scan/route.ts)
- Admin console "Run expiry (this user)" + "Run expiry (all users)" buttons in DevOps card
- Expiry logic:
  Items with all event/deadline/rsvp signals in past → archived (new/awaiting_reply) or overdue (awaiting_action)
  Only event/deadline/rsvp signals drive expiry — payment signals don't expire items
  new items, no signals, >7 days old → quietly_logged (transient alerts, disruption notices)
  awaiting_action items, no signals, >14 days old → quietly_logged
  awaiting_reply items, no signals, >60 days old → quietly_logged
- Proximity rescore also runs alongside expiry (same query, same batch)
- keel-admin: proxy route + "Run expiry" buttons in DevOps card
  Requires KEEL_APP_URL env var in keel-admin Vercel settings
